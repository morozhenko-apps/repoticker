# L10N-20 audit receipt — 2026-10-26

**Source branch:** `dev`, unpromoted. **Mode A** implementation.
This is an AI-assisted preliminary structural/semantic/contextual
audit, **not** a native-speaker review or Windows/KDE visual sign-off.
The prior feature order has been explicitly moved forward by the owner.

## Scope actually implemented

1. The exact 20 canonical locale codes (EN, RU, ES, PT-PT, DE, FR, IT,
   PL, HI, ZH-Hant, JA, NL, SV, TR, KO, BN, TH, ID, FIL, AR) are
   selectable by their native names. No `pt-BR`, `zh` or `tl` alias.
2. Native `save_settings` and `set_language` share one validated
   JSON-based code roster. Saved `en` and `ru` preferences retain
   their meanings. Settings only commits the chosen locale on OK.
3. Native tray actions and window titles use the same 20-language
   fixed-key catalog; command IDs remain unmodified.
4. Settings, About, status/usage, and card use localized presentation
   lookup. Arabic uses `dir=rtl`; saved roots and input paths are
   LTR. Provider-controlled names, repo paths, tokens and values
   remain data rather than template source.
5. Four contextual catalogs cover the extended Settings, auth and
   usage states. A separate card catalog covers 23 previously
   untranslated keys, including Git-safety descriptions and named
   `{name}` / `{count}` placeholders.

**Source-key inventory:** 90 Settings and 43 About/usage keys, with
131 unique source keys. All 131 are present per added locale in the
combined glossary. The 23 additional card keys and 7 native
menu/title keys are present per locale as well. These are static
catalog counts, **not** a statement of 100% of all executable UI
strings across the repository.

## Findings requiring further implementation, not merely screenshots

**L10N-A (high): Non-catalog native strings.** For example
`ci_notifications.rs` still emits the English notification title
`RepoTicker: CI failure` and some notification errors. Likewise
`github_session.rs` contains English security/authorization errors.
These were not automatically translated: doing so requires a
context-preserving presentation boundary, not translating protocol
errors or arbitrary provider text. This prevents a valid claim of
100% UI coverage.

**L10N-B (medium): Grammatically composed counters.** The Settings
repository-selection count is built from separate strings such as
`selected of`, `accessible`, and `inventory truncated`. This can
produce nonidiomatic ordering in Arabic, Hindi and CJK. Replace
with a complete locale-specific parameterized sentence rather than
concatenating translated fragments.

**L10N-C (medium): Plurals.** `syncReady`, `gitErrors` and the
selected-repository count use fixed templates in languages with
non-English plural morphology. Add `Intl.PluralRules`-backed forms
and per-locale context tests before semantic sign-off.

**L10N-D (medium): Provider values and numerical formatting.** The
usage model renders billing numbers in an English-US format before
localization. Locale-aware formatting and bidi-safe containment of
Latin runner/job names are still required; keep the raw values and
unavailable/unknown semantics unchanged.

**L10N-E (high): Windows tooltip runtime and OS acceptance.** The
separate rich usage tooltip remains physically unaccepted on Windows.
The existing read-only WebView2 title fallback is not equivalent to
the rich panel. Test this when the new candidate compiles.

**L10N-F (medium): Non-catalog UI errors.** Runtime-generated
`Invalid folder name` and other incidental native/frontend errors
need extraction or translation at a presentation boundary. Do not
translate raw exception text that may contain user paths or secrets.

## Exit criteria

L10N-20 is not eligible for `Passed` or source freeze until:
all six findings resolved, translation key and placeholder tests green
at exact source SHA, independently reviewed idiomatic text for each
locale, EN/RU regression, selected-account/credential invariants, and
real Windows/KDE font/RTL/overflow screenshots.

Keep `main` and the published release unchanged until these gates.
