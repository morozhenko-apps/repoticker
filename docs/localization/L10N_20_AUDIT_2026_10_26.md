## Findings requiring further implementation, not merely screenshots

**L10N-A (high): Non-catalog native strings.** For example
`ci_notifications.rs` still emits the English notification title
`RepoTicker: CI failure` and some notification errors. Likewise
`github_session.rs` contains English security/authorization errors.
These were not automatically translated: doing so requires a
context-preserving presentation boundary, not translating protocol
errors or arbitrary provider text. This prevents a valid claim of
100% UI coverage.

**L10N-B (medium): Grammatically composed counters.** The Settings
repository-selection count is built from separate strings such as
`selected of`, `accessible`, and `inventory truncated`. This can
produce nonidiomatic ordering in Arabic, Hindi and CJK. Replace
with a complete locale-specific parameterized sentence rather than
concatenating translated fragments.

**L10N-C (medium): Plurals.** `syncReady`, `gitErrors` and the
selected-repository count use fixed templates in languages with
non-English plural morphology. Add `Intl.PluralRules`-backed forms
and per-locale context tests before semantic sign-off.

**L10N-D (medium): Provider values and numerical formatting.** The
usage model renders billing numbers in an English-US format before
localization. Locale-aware formatting and bidi-safe containment of
Latin runner/job names are still required; keep the raw values and
unavailable/unknown semantics unchanged.

**L10N-E (high): Windows tooltip runtime and OS acceptance.** The
separate rich usage tooltip remains physically unaccepted on Windows.
The existing read-only WebView2 title fallback is not equivalent to
the rich panel. Test this when the new candidate compiles.

**L10N-F (medium): Non-catalog UI errors.** Runtime-generated
`Invalid folder name` and other incidental native/frontend errors
need extraction or translation at a presentation boundary. Do not
translate raw exception text that may contain user paths or secrets.
