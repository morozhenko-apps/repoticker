## Findings requiring further implementation, not merely screenshots

**L10N-A (high): Non-catalog native strings.** For example
`ci_notifications.rs` still emits the English notification title
`RepoTicker: CI failure` and some notification errors. Likewise
`github_session.rs` contains English security/authorization errors.
These were not automatically translated: doing so requires a
context-preserving presentation boundary, not translating protocol
errors or arbitrary provider text. This prevents a valid claim of
100% UI coverage.

**L10N-B (medium): Grammatically composed counters.** The Settings
repository-selection count is built from separate strings such as
`selected of`, `accessible`, and `inventory truncated`. This can
produce nonidiomatic ordering in Arabic, Hindi and CJK. Replace
with a complete locale-specific parameterized sentence rather than
concatenating translated fragments.

**L10N-C (medium): Plurals.** `syncReady`, `gitErrors` and the
selected-repository count use fixed templates in languages with
non-English plural morphology. Add `Intl.PluralRules`-backed forms
and per-locale context tests before semantic sign-off.

**L10N-D (medium): Provider values and numerical formatting.** The
usage model renders billing numbers in an English-US format before
localization. Locale-aware formatting and bidi-safe containment of
Latin runner/job names are still required; keep the raw values and
unavailable/unknown semantics unchanged.

**L10N-E (high): Windows tooltip runtime and OS acceptance.** The
separate rich usage tooltip remains physically unaccepted on Windows.
The existing read-only WebView2 title fallback is not equivalent to
the rich panel. Test this when the new candidate compiles.

**L10N-F (medium): Non-catalog UI errors.** Runtime-generated
`Invalid folder name` and other incidental native/frontend errors
need extraction or translation at a presentation boundary. Do not
translate raw exception text that may contain user paths or secrets.

## 2026-10-27, 09:43 UTC — Mode A continuation: exact known error messages

### Root cause and evidence

**Expected:** a known static Settings/GitHub error appears in the
selected saved or draft language, while unknown external errors remain
exactly as returned.

**Observed source:** `settings.mjs` passes `String(error)` from
`select_repository_root`, `github_begin`, `save_settings`,
`autostart_set_enabled` and wallet commands to `message` or
`githubMessage`. These handlers run `settingsText(language, error)`
but the known native error strings are missing from EN/RU/new locale
dictionaries. The local ignored-folder picker throws
`Invalid folder name`, which has no translated key. Several native
GitHub errors are deliberately static; provider-controlled errors are
not guaranteed static or safe to translate.

Possible causes considered:
1. known native/static error absent from all dictionaries;
2. raw native error passed directly through generic message functions;
3. locale mismatch between saved and current Settings draft;
4. unknown provider text is intentionally left untranslated;
5. native path or Git error contains dynamic data;
6. a legacy English-only error is not represented in the key inventory.

**Confirmed high-confidence causes:** (1) and (2). Focused diagnostics:
exact-key inventory of native `Err` and `public_error` literals,
frontend `throw Error` sites, and the lexical lookup contract; do not
collect credentials, paths or network responses.

### Scoped plan and rollback

- **Change:** introduce a dedicated fixed-key, exact-match dictionary
  for user-facing local errors across the 20 locale roster. Reuse the
  existing presentation catalog lookup in Settings, not native error
  parsing or new provider calls. Include the static Rust
  folder-dialog, OAuth and autostart-recovery error texts.
- **Safety:** keys are exact full strings only. Never substring-replace,
  interpolate, discard, log or translate unknown exception text.
  Settings Cancel and Save/OK semantics do not change. No
  authorization or persistent format changes.
- **Audit:** add deterministic parity, fallback, no-secret,
  no-rewritten-path tests; check Japanese, Arabic, Polish, Portugal
  Portuguese and Russian known errors explicitly. Compare known error
  keys against native/JS site inventory. Execute the stable suite at
  the final validation gate only.
- **Rollback:** remove one error catalog import and the text projection
  bridge. Native APIs, stored locales and OS dialogs remain untouched.
- **Out of scope:** translating arbitrary Rust/Git exceptions or
  claiming independent 20/20 native-speaker approval. Windows tooltip
  and per-OS layout acceptance remain separate gate E.
