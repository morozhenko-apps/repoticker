## Focused mutation review amendment (same four test cases)

The source-exact isolated V8 diagnostic ran 15/15 registered scenario bodies with actual production module sources and a lightweight Node-test shim, **not** official Node26 `node --test`. A bounded mutant probe of the four new tests detected two of four modified guards:

- Caught: refresh throttle `<` changed to `<=`; native publication-tail rejection recovery removed.
- **Not yet caught:** removal of the independent `busy` guard; removal of the queued-publication `revision` check.

These are weaknesses in the existing two assertions, not evidence that the production behavior is defective. The most likely causes are independent throttle prevention hiding the missing busy guard, and no obsolete queued write existing when the disconnected state was asserted. Assert it cannot collect concurrently, and that precisely one requested trailing `tasks` read executes after the in-flight full read settles. When the first publish rejects, assert that the obsolete queued `Checking GitHub connection...` message is **not** delivered and only the final disconnected/unknown state reaches native IPC.
